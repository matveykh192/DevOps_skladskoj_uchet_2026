# Резервное копирование и восстановление PostgreSQL

Команды запускаются из корня репозитория в PowerShell при работающем Docker Desktop.

## Основная учебная база `warehouse_db`

```powershell
make backup
make restore
```

- `make backup` создаёт `backups/warehouse_db.dump` с помощью `pg_dump -Fc`. **Не очищает и не пересоздаёт** основную базу.
- `make restore` проверяет архив и восстанавливает его через `pg_restore` в **отдельную временную базу** `warehouse_restore_verify` того же PostgreSQL. Проверяет ревизию Alembic `003_minimum_stock` и доступность материалов, затем удаляет только эту временную базу. **Основная база не изменяется.**
- Если нужно реально перезаписать основную учебную БД архивом, предусмотрен отдельный опасный режим:

```powershell
make restore-main RESTORE_CONFIRM=RESTORE_WAREHOUSE_DB
```

Это **разрушительная операция**: сначала создаётся дополнительный резервный архив `backups/warehouse_before_restore_YYYYMMDDTHHMMSSZ.dump`, затем останавливается приложение, удаляется и создаётся заново именно `warehouse_db`, после чего выполняется `pg_restore`. При неудаче восстановления приложение остаётся остановленным, сохранённый страховочный дамп можно использовать для повторной операции. После успеха: `docker compose up -d app`.

У **restore-main** нет необходимости в обычной проверке лабораторной; запускать его только если действительно требуется вернуть старое состояние. Контрольный restore через `make restore` безопаснее и достаточен для проверки архива.

По умолчанию восстанавливается **текущий** архив `backups/warehouse_db.dump`. Прежний `backups/warehouse_before_upgrade.dump` не перезаписывается. Архивы должны быть в `.gitignore`.

## Автоматическая изолированная проверка

```powershell
make backup-check
make verify
```

`make backup-check` использует **только** проект Compose `warehouse-lr3-test` и временную базу `warehouse_backup_verify`: создаёт материал с остатком 12.500 и минимумом 5.000, архивирует БД, намеренно удаляет запись, восстанавливает и сравнивает остаток, минимум и ревизию Alembic. Команда `make verify` продолжает запускать эту изолированную проверку, а не трогает основную БД.

Для старого демонстрационного сценария доступны `make backup-demo` и `make restore-demo`. Первый пересоздаёт только демонстрационную базу `warehouse_backup_demo` в тестовом Compose-проекте.

## Проверки безопасности

Основная и тестовая базы разделены. Скрипт основной базы сверяет значения `POSTGRES_USER` и `POSTGRES_DB` и не принимает произвольные имена целевых БД. Каждый новый архив проверяется на сигнатуру `PGDMP`, пригодность для чтения `pg_restore -l` и SHA256. Путь с архивами `backups/` не должен попадать в Git.
