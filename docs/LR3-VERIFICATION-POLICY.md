# Политика обязательных проверок ЛР №3

Любое изменение исходного кода, тестов, SQL, миграций или конфигурации проверок должно пройти `make verify` перед Pull Request / слиянием. Для Windows PowerShell до установки GNU Make предусмотрена эквивалентная команда `./scripts/verify.ps1`. Финальная защита должна включать реальное выполнение **`make verify`** (например, через Git Bash с установленным GNU Make, WSL или Linux).

Обязательный минимум на текущем этапе: Ruff lint, Ruff format --check, Bandit, pytest (все тесты) с branch coverage не ниже 60%. В последующих этапах сюда будут добавлены проверки Alembic и резервного копирования, не затрагивающие рабочие данные.

Запрещено без письменного обоснования в Pull Request:
- пропускать тесты (`skip`, `xfail`) или отключать их обнаружение;
- снижать порог 60%, удалять проверяемые модули из `coverage` ради повышения процента;
- выключать Ruff/Bandit, подавлять правила (`noqa`, `nosec`, `per-file-ignores`, `exclude`) для обхода ошибок;
- игнорировать коды завершения инструментов в Makefile/PowerShell/CI;
- тестировать разрушительные операции на рабочей PostgreSQL.

Любое исключение требует записи: затронутый файл и правило, причина, оценка риска, альтернативная проверка, ответственный и дата согласования преподавателем/ревьюером. Исключения должны быть минимальными и обозримыми.

## Запуск

Windows VS Code PowerShell: `./scripts/verify.ps1`.
GNU Make (Git Bash с make, Linux, WSL): `make verify`.

Отчёты по тестам после успешного запуска доступны на хосте в `reports/junit.xml` и `reports/coverage.xml`. Фактический результат проверяется по выводу команд, а не по наличию файла отчёта (он мог остаться от предыдущего запуска).

ВАЖНО: текущий `make verify` ещё не включает миграции и restore: они появятся на следующих этапах. Нельзя называть такой прогон финальным выполнением всех 15 пунктов ЛР №3.
